# RobotStudio 프로젝트 — ABB 타이어 제조 셀 (인수인계 문서)

이 폴더는 학습/개인 프로젝트로 진행 중인 **ABB 로봇 기반 타이어 자동화 공정 시뮬레이션**입니다.
이 문서는 컴퓨터를 바꾸거나 새 세션을 시작할 때, AI가 처음부터 다시 설명 안 들어도 되도록
지금까지의 작업 내용·결정 이유·미해결 이슈를 정리한 인수인계 노트입니다.

## 저장소 / Git 정보

- GitHub: `https://github.com/warrocking/Study.git` (origin, branch `master`)
- 이 저장소는 여러 학습 주제(C, CPP, OpenCV, PLC, Ros2 등)를 한 데 모아둔 개인 스터디 저장소이고,

## 타이어 공정 흐름 (project.mod)

```
컨베이어1(di21) → 프레스(di22, 냉각 스윕 포함) → 컨베이어2(di23, 색상 판별)
  ├─ 검정(정상, di04) → 컨베이어3 → tool1 비드코팅(di24) → tool2 원형스프레이(di25)
  │                                                          → 창고 적재(di26)
  └─ 흰색(불량, di05) → 트래시로 즉시 분리, 이번 사이클 강제 종료
```

- **창고 적재(di26)**: `Count`(0~3)로 박스 1~4에 순서대로 적재. `Count`가 4가 되면 박스 4개를
  한 번에 집어서 `p_EndBox`로 옮기고 `Count`를 0으로 리셋.
- **서버 동작**: `Count > 0`이면 클라이언트 재접속 시 `"start"` 없이 자동으로 이어서 생산.
  `Count = 0`이면 반드시 `"start"` 텍스트를 받아야 시작. 비상정지(`Trap_EStop`)는 `Count`를
  강제로 0으로 리셋함.

## 코드 스타일/컨벤션 (반드시 지킬 것)

1. **RAPID 주석은 영어로만 작성.** RobotStudio가 저장할 때 한글 주석을 깨뜨리거나
   통째로 지워버리는 문제를 여러 번 겪어서, 이후로는 전부 영어 주석으로 통일했음.
   앞으로도 한글 주석 넣지 말 것.
2. **들여쓰기는 4칸씩 단계별 증가.** `MODULE`=0칸, `VAR`/`PROC`/`ENDPROC`=4칸,
   PROC 본문=8칸, 중첩될 때마다 +4칸.
3. **위치가 안 바뀌는 순수 회전 동작은 상황에 따라 `MoveJ`가 더 안전함.** ABB 손목 특이점
   (axis5=0) 문제 때문에 `MoveL`로 큰 각도 in-place 회전을 하면 축4/6이 급격히 재구성되며
   튀는 문제가 실제로 있었음(`tool1`의 180도 회전은 `MoveJ` 사용 확정). 다만 냉각 스윕
   (`Reorient_CoolingSweep`)은 여러 각도(5/10/15/20/25/30도)와 `MoveJ`/`MoveL`을 직접
   실기로 비교 테스트한 끝에 **`MoveL` + 25도 + 45도씩 8지점**으로 최종 확정됨 — 이건
   일반 규칙이 아니라 이 특정 위치에서 실측으로 검증된 결과이니, 다른 위치에 그대로
   적용하지 말고 다시 테스트할 것.
4. **저장소 박스 카운트는 `TEST Count` / `CASE 0~3` 패턴**으로 처리하고,
   각 CASE에서 `Count := Count + 1`.
5. **그리퍼는 용도에 따라 의미가 반대.** 타이어: `Grip_on`=닫아서 잡기, `Grip_off`=열어서 놓기.
   4박스 일괄 이송(걸쇠 방식): `Grip_on`=벌려서 준비, `Grip_off`=오므려서 박스를 문다.
   헷갈리기 쉬우니 di26 블록 주석 참고.

## 아직 안 고친 이슈 (다음에 확인할 것)

1. **`di23`의 `count_White` 처리 — CASE 2/3/4가 비어있음.** 프로그램 시작 후 첫 번째
   불량(흰색) 타이어만 정상적으로 트래시에 놓이고, 두 번째부터는 그리퍼가 안 놓임(비어있는
   CASE라서). 사용자가 "깔끔한 의도된 설계"를 원해서 발표자료에는 이 버그를 안 넣기로 했지만,
   **실제 코드에는 아직 남아있는 미해결 버그임.**
2. **불량 타이어 발생 시 `processRunning := FALSE`로 전체 사이클이 끝남** (검정/정상 분기는
   안 그럼) — 비대칭 동작. 의도인지 재확인 필요.
3. `count_White`는 어디서도 리셋 안 됨(비상정지에서도 리셋 안 됨) — 위 1번 버그가 프로그램
   실행 중 딱 한 번만 정상 동작하고 이후로는 계속 발생.
4. `Grip_on`/`Grip_off`가 `WaitDI`에 타임아웃이 없어서, 센서가 응답 안 하면 로봇이 무한정
   멈춤. 아직 안 고쳐짐.

## 사용자(작업자) 관련 참고사항

- RobotStudio에서 직접 좌표 티칭 후 project.mod를 그때그때 갱신하는 방식으로 작업함 —
  파일이 세션 중간중간 외부에서 바뀌어 있을 수 있으니, 수정 전엔 항상 다시 읽어서 확인할 것.
- 각도/속도 등 파라미터는 "일단 작게 해보고 되면 값 올려보기"(5도→10도→15도...) 식으로
  실기 검증하며 점진적으로 확정하는 걸 선호함.
- PPT(발표자료)는 별도의 AI 도구로 만들고 있고, 거기 들어갈 순서도가 실제 로직과 안 맞을 때
  그 AI에게 보낼 프롬프트를 대신 작성해주는 식으로 도움. (발표용 자료는 "의도된 설계"를
  보여주는 걸 선호 — 위 known-issue의 실제 버그는 발표자료엔 안 넣음.)
