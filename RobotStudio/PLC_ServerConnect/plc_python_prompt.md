# [프롬프트] 미쓰비시 Q03UDV PLC ↔ Python 통신 프로그램 작성 요청

아래 내용을 바탕으로 파이썬 프로그램을 작성해줘. 나는 PLC 초보이고, 설명은 한국어로,
코드에는 한국어 주석을 충분히 달아줘. 애매한 부분은 먼저 질문해줘.

---

## 1. 목표
파이썬으로 미쓰비시 Q 시리즈 PLC와 **이더넷(MC 프로토콜)**으로 통신해서,
PLC의 디바이스(메모리) 값을 **읽고 쓰는** 프로그램을 만들고 싶어.
아래 환경/파라미터에 정확히 맞춰서 작성해줘.

## 2. 하드웨어 / 개발 환경
- PLC: 미쓰비시 **MELSEC-Q 시리즈**, CPU = **Q03UDVCPU** (내장 이더넷 포트 + USB 있음)
- 프로그래밍 도구: **GX Works2** (Simple Project + Use Label, 언어는 Ladder, Q mode)
- 통신 방식: **MC Protocol (MELSEC Communication Protocol) 3E 프레임, TCP**, CPU **내장 이더넷 포트** 사용
- 파이썬 라이브러리: **pymcprotocol** (`pip install pymcprotocol`), **`Type3E()`** 사용 (Q 시리즈용)
  - 대안 라이브러리: pymelsec (더 많은 기능). 특별한 이유 없으면 pymcprotocol로.
- 실행 환경: Windows 네이티브 + Python 3.x (필요하면 조정 가능)

## 3. 연결 파라미터 (GX Works2에서 이미 설정 완료)
- **PLC IP 주소: `192.168.3.39`**
- **PLC MC 프로토콜 수신 포트(TCP): `1025`**
- 내 PC(노트북) IP: `192.168.3.33` (PLC와 같은 서브넷, 마스크 `255.255.255.0`)
- 통신 데이터 코드: **Binary** (pymcprotocol 기본값과 동일)
- 쓰기 허용: GX Works2에서 **"Enable online change (FTP, MC Protocol)" 체크됨** → 파이썬에서 쓰기 가능
- 접속 구조: **PC가 클라이언트**로 PLC(`192.168.3.39:1025`)에 **접속**하고, **PLC는 서버로 대기**.
  하나의 TCP 연결로 요청(읽기/쓰기)과 응답(데이터)이 오감.
  → 코드에서 접속 대상 IP는 **PLC IP(192.168.3.39)**. 내 PC IP는 코드에 넣지 않음.

## 4. 디바이스 맵 (내 래더 프로그램 기준)
아래는 내 프로그램의 디바이스야. **스크립트 맨 위에 상수/딕셔너리로 빼서 쉽게 바꿀 수 있게** 해줘.
(주소는 내 현재 프로그램 기준이라 실제와 다를 수 있으니, 값만 바꾸면 되도록 만들어줘.)

**입력 (비트, X) — 센서**
- `X23` = 고주파센서 (금속 감지)
- `X24` = 용량형센서 (물품 존재 감지)
- `X25` = 근접포토센서 (흰색 반사 감지)
- `X29` = 물품도착포토

**내부 릴레이 (비트, M)**
- `M9215` = 시작
- `M9214` = 공급전진, `M9213` = 공급후진, `M9212` = 컨구동(컨베이어 구동)
- `M9198` = 금속감지, `M9196` = 흰비금속감지, `M9197` = 검비금속감지

**출력 (비트, Y)**
- `Y40` = 공급전솔, `Y41` = 공급후솔, `Y48` = 컨베이어
- `Y44` = 경광녹색(흰 비금속), `Y45` = 경광황색(검 비금속), `Y46` = 경광적색(금속)
- `Y1006` = 물품도착 표시등

> 참고: 이 기계는 부품을 컨베이어로 이송하며 3개 센서로 판별하는 분류기야.
> 고주파=금속, (금속 아님 + 근접포토 흰색)=흰 비금속, (금속 아님 + 흰색 아님)=검 비금속.

## 5. 만들어줄 것
1. **재사용 가능한 통신 모듈** (`PLCClient` 클래스):
   - `connect()`, `close()`, 컨텍스트 매니저(`with`) 지원
   - `read_bits(device, size)`, `read_words(device, size)`
   - `write_bits(device, values)`, `write_words(device, values)`
   - 내부적으로 pymcprotocol `Type3E()`의 `batchread_bitunits` / `batchread_wordunits` /
     `batchwrite_bitunits` / `batchwrite_wordunits` 를 감싸기
   - 연결 끊김/타임아웃 시 **자동 재접속(지수 백오프)**, 실패는 로그로 남기기
2. **예제 스크립트 3개**:
   - (a) **상태 모니터**: 센서/분류/시퀀스의 X·M·Y 값을 주기적으로 읽어 콘솔에 보기 좋게 출력
     (예: 표 형태, 켜짐/꺼짐 표시). 연속 디바이스는 한 번에 batch 읽기.
   - (b) **분류 집계 로거**: 금속/흰/검 분류 플래그(M9198/M9196/M9197)를 폴링하면서
     **이전 값 대비 새로 켜질 때만(상승 에지) +1** 카운트하고, 타임스탬프와 함께 **CSV로 기록**.
     (래더에 별도 카운터를 넣지 않아도 PC 쪽에서 세는 방식으로.)
   - (c) **명령 전송 예제**: 시작 비트(M9215)를 켜는 등 **안전한 쓰기** 예시 (아래 주의사항 참고).
3. **설정 파일/상단 상수**: `PLC_IP`, `PLC_PORT`, 디바이스 주소 딕셔너리, 폴링 주기 등.

## 6. 요구사항 (코드 품질)
- pymcprotocol 사용: `Type3E()` → `connect(PLC_IP, PLC_PORT)`.
  워드 디바이스(D 등)는 `batchread_wordunits`, 비트 디바이스(X/Y/M)는 `batchread_bitunits` /
  `batchwrite_bitunits` 사용.
- 예외/타임아웃 처리, 연결 끊기면 자동 재접속(백오프). 통신 실패를 **조용히 삼키지 말고** 로그로.
- `with` 또는 `try/finally`로 연결 정리(`close`).
- `logging` 모듈로 로그, CSV 기록은 표준 `csv` 사용(원하면 pandas도 가능).
- 폴링 루프는 **Ctrl+C로 안전하게 종료**되게.
- 연속된 디바이스는 batch로 묶어 한 번에 읽기(예: `X23`~`X29`, `M9196`~`M9198`).
- 타입 힌트, 함수/클래스 분리, 한국어 주석 충분히.

## 7. 제약 / 꼭 지켜야 할 주의사항
- Q 시리즈이므로 **`Type3E()`** 사용 (A/FX 시리즈 아님).
- 접속 대상 IP는 **PLC(192.168.3.39)**. 내 PC IP(192.168.3.33)는 코드에 넣지 않음.
- 쓰기는 GX Works2의 online change가 켜져 있어야 동작함(이미 켜둠).
- **안전**: 출력(Y)이나 실제 설비를 직접 움직이는 디바이스에 함부로 쓰지 마.
  쓰기 예제는 **명령용 M 릴레이**(예: 시작 M9215) 위주로 하고, "실제 가동 중에는 사람이
  확인 후 실행하라"는 안전 주석을 달아줘. 위험한 직접 출력 제어는 기본으로 만들지 마.
- X/Y는 **GX Works2에 보이는 주소 문자열 그대로** 사용(예: `"X23"`, `"Y44"`, `"M9198"`, `"D0"`).
  (X/Y는 16진 주소일 수 있으니 라이브러리에 문자열로 그대로 전달.)
- 통신 데이터 코드는 Binary(기본값). 만약 ASCII로 바꿔야 하면 `setaccessopt(commtype="ascii")` 안내.

## 8. 출력 형식
- **파일 구성 제안**(예: `config.py`, `plc_client.py`, `monitor.py`, `logger.py`, `send_command.py`)과
  각 파일의 **전체 코드**.
- **실행 방법**(설치 명령 `pip install pymcprotocol`, 각 스크립트 실행 명령)과 **예상 출력 예시**.
- 내가 바꿔야 할 부분(디바이스 주소, IP, 포트 등)을 **맨 위에 명확히 표시**.
- **연결이 안 될 때 점검 순서**도 간단히 정리:
  1) PC에서 `ping 192.168.3.39` 응답 확인
  2) PC와 PLC가 같은 서브넷(192.168.3.x)인지, IP 충돌 없는지
  3) GX Works2 Open Setting이 **MC Protocol / TCP / 포트 1025**인지, PLC에 쓰기+리셋 했는지
  4) PC 방화벽이 파이썬/포트를 막는지
  5) 포트 번호가 GX Works2(설정)와 파이썬(접속)에서 일치하는지

먼저 위 내용으로 전체 코드를 작성해줘. 그다음 내가 상태 모니터부터 돌려볼 수 있게
가장 간단한 실행 순서를 알려줘.
